# Data sources, conventions and known limitations

Everything under `data/` is input; everything under `results/` and `figures/` is regenerated by
`python scripts/make_figures.py`.

| Path | What it is |
|---|---|
| `data/raw/KtoPi_horn_raw_yields.csv` | Yields behind the horn plot, one row per experiment / energy / species / centrality, with the **source** and **feed-down convention** of every row |
| `data/thermal_fist/inputs/*.dat` (15 files) | Ratio files loaded into Thermal-FIST (needed only to repeat the fits) |
| `data/thermal_fist/outputs/fit_*.txt` (16 files) | The valid Thermal-FIST output files, one per fit; the code reads these |
| `data/reference/star_published_TableVIII_GCE_0-5.csv` | STAR's published fits used as the benchmark in Fig. 2 |

## Thermal-FIST input files (`data/thermal_fist/inputs/`)

Each `.dat` file lists the ratios fitted at one energy: `is_fitted, pdg1, pdg2, feeddown1, feeddown2, value, error`. Errors are the two yields' errors (statistical and systematic already combined) added in quadrature, treating the two yields as uncorrelated (conservative).

| Files | Ratios | Built from | Feed-down codes |
|---|---|---|---|
| `STAR-AuAu*GeV-0-5-ratios.dat` (7.7, 11.5, 19.6, 27, 39 GeV) | pi-/pi+, K-/K+, pbar/p, K-/pi-, pbar/pi- | STAR Table VI, 0-5% | 3 for pi and K; 2 for p, pbar |
| `NA49-PbPb20A/30A-ratios.dat` | same five | NA49 Table I (pi, K) and Table III (p, pbar) | 3 for all |
| `NA49-PbPb20A/30A-ratios-pInclusive.dat` | same five | same | 3 for pi, K; 2 for p, pbar (sensitivity test) |
| `ALICE-PbPb2p76TeV-0-5-ratios-for-fit.dat` | same five | ALICE 0-5%: pi+ 733+-54, pi- 732+-52, K 109+-9, p 34+-3, pbar 33+-3 | 3 for all |
| `STARFXT-AuAu3p2/3p5/3p9/4p5GeV-ratios.dat` | pi-/pi+, K-/K+, K+/pi+ | FXT file, near-midrapidity dN/dy, primordial pi | 3 |
| `HADES-AuAu2p4GeV-ratios.dat` | pi-/pi+, K+/pi+, K-/K+ | pi: Table 3 of 2005.08774 (0-10%); K+ 0-10% and published K-/K+ (0-20%) of 1703.08418 | 3 |

## Thermal-FIST output files (`data/thermal_fist/outputs/fit_*.txt`)

All fits: ideal HRG, quantum statistics, zero-width resonances, PDG2025 list. Q/B = 0.4 and zero net strangeness, except ALICE (mu_Q = 0).

| Files | Ensemble | Free parameters | Fixed |
|---|---|---|---|
| `fit_STAR_*`, `fit_NA49_*`, `fit_ALICE_*` | grand-canonical | T, mu_B, gamma_S | R (volume cancels in ratios) |
| `fit_HADES_..._grandcanonical_muB790fixed` | grand-canonical | T | mu_B = 790 MeV, gamma_S = 1 |
| `fit_HADES_..._strangenesscanonical_muB790fixed` | strangeness-canonical | T, R_c | mu_B = 790 MeV, gamma_S = 1 |
| `fit_FXT_3p2/3p5/3p9/4p5..._muB698/669/634/587fixed` | grand-canonical | T | mu_B from the Cleymans curve, gamma_S = 1 |

Fixed mu_B values come from the Cleymans curve, not from these data; their effect on T is not included in the fit errors.

Fits that were run but are **not** included (superseded or failed): runs with mu_B left at the wrong value (the first FXT runs at 790 MeV, the STAR runs with mu_B fixed at 400 MeV), STAR 7.7 GeV with gamma_S fixed, a HADES strangeness-canonical run whose R_c hit its 15 fm limit, and two HADES runs (mu_B = 711 and 869 MeV) that ran onto the T = 30 MeV and R_c = 30 fm limits.

## Known limitations (state them in the paper)

- Yields were transcribed by hand; the FXT source and the HADES pion feed-down convention are still to be confirmed.
- The horn mixes 4pi multiplicities (HADES) and mid-rapidity dN/dy, and different centralities (0-5%, 7.2%, 0-10%, HADES K- at 0-20%). Where 0-5% and 5-10% were both available they were averaged without weights.
- Ratio errors are treated as uncorrelated, so chi2/ndf is small and fit errors are conservative.
- Low-energy (HADES, FXT) fits use three ratios and a fixed mu_B; the HADES strangeness-canonical fit has 1 degree of freedom and R_c = 21 fm (larger than the nucleus).
- Only pi, K, p were fitted; Lambda and Xi (included in STAR's published fits) were not.

## Data correction (October 2026)

The first version of `KtoPi_horn_raw_yields.csv` listed every **STAR FXT** row twice (16 duplicate
rows, 92 rows instead of 76). Because the code averages rows that share an energy and species, with
error sqrt(sum(err^2))/n, the duplicates made the **FXT K/pi error bars 1/sqrt(2) = 0.71 times
too small** at 3.2, 3.5, 3.9 and 4.5 GeV. The central values were not affected, and neither were the
Thermal-FIST fits, whose `.dat` input files used the correct errors. The duplicates are removed
here and `horn.load_raw_yields` now raises an error if a row is ever listed twice.

| sqrt(s_NN) (GeV) | K+/pi+ error before | after | K-/pi- error before | after |
|---|---|---|---|---|
| 3.2 | 0.0052 | 0.0074 | 0.00030 | 0.00042 |
| 3.5 | 0.0082 | 0.0117 | 0.00068 | 0.00096 |
| 3.9 | 0.0125 | 0.0177 | 0.00179 | 0.00253 |
| 4.5 | 0.0167 | 0.0236 | 0.00213 | 0.00301 |

## Notes on the Thermal-FIST output files

The first line of each `fit_*.txt` originally contained the absolute path of the input file on the
machine where the fit was run. The directory part was removed so that only the file name remains
(`Thermal fit to HADES-AuAu2p4GeV-ratios.dat within ...`); nothing else in the files was changed.
